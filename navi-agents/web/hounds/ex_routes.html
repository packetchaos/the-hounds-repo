“Search every application route — and tag the assets on it.”
The Wolfhound, large enough to run down a wolf — here it runs down the application routes navi builds from your findings.

The Problem

navi groups findings into application routes, and that is where exposure concentrates by app. Pulling one app's routes — and tagging the assets on them — shouldn't need a hand-written query.

What It Does

Wolfhound searches the application routes in navi.db by app name or vulnerability type, with each route's total findings and plugins. Tag applies Route : <name> to every asset on that route.

At a glance

Key Capabilities

  • Search routes — by app name or vulnerability type.
  • Route detail — total findings and the plugins behind each route.
  • Tag a route — Route : <name> on every asset on that route, with an editable value, behind the write gate and a confirm.
  • Email the result — send the rows through Gabriel.

How It Works

Wolfhound reads the application routes in your local navi.db without changing it; results page on the server, 20 rows a page (up to 50). Tags go through navi's tag command.

Who It's For

Analysts scoping an application's exposure and owners looking up their app.

Works Better With

Atlas assigns owners to these routes, Cavall names the custom apps among them, and Greyhound does the same for filesystem paths.
