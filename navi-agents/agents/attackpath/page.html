Fenrir Hound

🕸️ Attack Path Analysis

Fenrir shows how the weaknesses Tenable already found chain together to reach your crown jewels: remotely exploitable vulnerabilities, local privilege escalation, credentials shared across hosts, NTLM relay, domain-controller flaws, and failed compliance controls (LAPS, SMB signing, LLMNR, WDigest, sudo…) that make each step easier. Then it finds the fixes that break the most paths. Everything comes from navi.db; reachability is inferred (no flow data), and every step shows its evidence. Tags the assets Attack Path : Entry Point | Pivot | Target | Choke Point; writes are gated and tracked in the Tagging log.

Attack map

Left to right: attacker → ways in → pivots → crown jewels. Hover to trace, click a host, credential or step for its evidence. Scroll to zoom, drag to pan. Line thickness = how many mapped paths use that step.

Attack paths

Each row is one route to a crown jewel. Likelihood multiplies the step likelihoods (KEV and high EPSS score highest). Risk = likelihood × the target's ACR. Up to five diverse routes per crown jewel: the most likely, then the best that avoids the domain, uses account reuse, uses relay, or uses a failed control. Click 🗺 to light a path up on the map, or the row to see every step's evidence.

Choke points — every fix on a mapped path

Ranked by exposure cut if only this one fix is applied (alternative routes recalculated). On mapped routes = how many of the shown routes use it. Cuts off = crown jewels left with no route at all — often 0, because attackers have alternatives (that's why the bundle matters). Tag the assets that carry a fix Attack Path : Choke Point.
